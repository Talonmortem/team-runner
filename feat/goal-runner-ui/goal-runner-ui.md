# Goal runner UI

Реализовать пользовательский план: единая конфигурация девяти ролей, снимок на попытку,
общий supervised launcher Codex/Claude, локальный Python HTTP сервер и HTML/CSS/JS в team/.
CLI сохраняется. Приоритет defaults → сохранённый файл → overrides координатора.

Порядок: конфигурация и атомарное хранение; реестр ресурсов и команды runner; HTTP/UI;
тесты конфигурации, гонок, восстановления, pause/stop/retry и браузерный цикл.

Приёмка: выбранные параметры каждой роли передаются запуску; неизвестные фактические
параметры явно неизвестны; stop изолирован и подтверждён до retry; закрытие вкладки
и рестарт HTTP не останавливают runner; старый dispatch не запускается повторно.
Без новых зависимостей, удалённых хостов, нативного плагина и копирования ключей.

## Продолжение: пять улучшений

1. Журнал request ID до mutation; bootstrap-квитанция терминала; reconcile через UI/CLI по доказательствам.
2. Явный reuse implementer/tester только в одной функции/попытке с тем же runtime/profile/provider/model/effort и живой identity; reviewer свежий.
3. Сопоставление текущего снимка, следующего эффективного конфига, CLI overrides и известных фактов.
4. Fault injection между внешним эффектом и сохранением, потеря stop-ответа, прерывание команды.
5. Автоматический browser fixture: настройки/start/question/gates/pause/stop/retry/recovery и повторное открытие.

Критерии: нет двойных процессов/dispatch, чужие identity не принимаются; неизвестное остаётся заблокированным;
UI не потребляет mailbox; browser test выполняется одной командой и очищает только свои ресурсы.
