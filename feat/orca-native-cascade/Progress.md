### Реализация

- CLI `cascade` подключён к каталогу Runner. Реестр сохраняет исходный SHA, очередь, карточки, настройки ролей и операции в XDG. Обычный Runner использует ту же аренду для исходного и дочерних checkout. Остановка сначала запрещает новые эффекты, затем сверяет квитанции и освобождает аренды после подтверждения выхода процессов.
- Адаптер Orca сохраняет Run, Task, Dispatch и точную идентичность панелей. Параметр `--branch` закрепляет имя `team-runner/cascade-<UUID>` независимо от настройки префикса Orca. Для нативного чата Run с пустым `coordinator_handle` подтверждается через `run-current` из той же аутентифицированной сессии.
- В Orca 1.4.265 подтверждены выборка inbox по точному получателю, порядок `sequence DESC` и выдача прочитанных сообщений. Проверен запрос с пределом 4096. `request-show` возвращает UUID, метод и квитанцию, а сверка аргументов опирается на сохранённую операцию, точное назначение и проверку полезной нагрузки самой Orca при повторе UUID.
- Координатор запрашивает якорь через родительский Run. Менеджер отправляет сообщение на точный Dispatch координатора, а Orca перенаправляет его в почту дочернего Run. Координатор может принять точную первую запись при потере квитанции менеджера.
- Команды проверки и дополнительные входы задаются блоком `cascade-verification` в замороженной карточке. Тестировщик ссылается на квитанции Runner. Ревьюер проверяет тот же SHA, манифест и чистые границы. После приёмки независимый сдвиг ветки не влияет на базу преемника.

### Проверка Docker на рабочем хосте

- Runner закрепляет локальный образ Docker по ID на исполнение. Orca открывает терминал роли и привязывает точный Dispatch. Codex работает целиком в контейнере с read-only монтированиями кандидата, метаданных Git и материалов. Отчёт, сессия Codex и `CARGO_TARGET_DIR` размещаются в каталоге артефактов роли. Провайдер и сдача отчёта доступны через отдельные сокеты. Для контейнера отключена внешняя сеть.
- В отдельном Orca 1.4.265 на одноразовой копии AI Story с SHA `5bd6b4317040cc9c9b2c30a976e81ad911737997` прошли все 292 теста `cargo test --locked --offline -p ai-story-core --jobs 2`. Запись отчётного файла прошла. Shell получил `EROFS` на кандидате, встроенный `apply_patch` также получил отказ. SHA, хеш проверенного файла и чистота checkout после пробы совпали.
- Для осиротевшего контейнера Runner после fencing Orca и подтверждения выхода исходного процесса журналирует очистку по точному Docker ID и сверяет отсутствие контейнера. Если Orca подтвердила доставку ввода, но не увидела старт хода Codex, Runner сохраняет точный Dispatch и ждёт его отчёт. Повторной доставки из этой квитанции нет.

Orca показала `completed/succeeded`. После последних изменений прошли 52 теста каскада и три самостоятельные проверки вспомогательных команд.
