# Понятный UI цели и команды

Дата: 2026-10-17. Реализация не начата.

Общие контракты: [goal-autonomous-runner.md](../goal-autonomous-runner.md).
Зависимости: contracts, autonomy, agent-interface.

## Текущее состояние и область
Перед целью расположены сервисы, каталог и таблица всех моделей. Одновременно видны Start/Resume/Retry/Reconcile,
порты и управление сервисами. Агенты и история выводят технические структуры, главный прогресс не выделен.
Область: runner-ui/index.html, style.css, app.js; адаптер HTTP только для нового общего контракта.
Без frontend dependencies, внешних шрифтов и визуальных ассетов по сети.

## Макет и поведение
1. Компактный header: Team Runner, подтверждённость соединения, выбранный проект/workspace.
2. Главная карточка: название цели, состояние, текущий пункт/попытка, выполнено N из M и прогресс.
   Завершение очереди и успешную финальную приёмку различать; N=M не означает готовность цели.
3. Одна основная кнопка по available_actions: «Выполнить» или «Продолжить». При работе — «Пауза после пункта»
   и «Остановить». Повтор появляется при соответствующей блокировке; неоднозначный retry требует выбора,
   обновление снимка и дополнительная попытка никогда не включаются незаметно.
4. Над агентами — блок «Нужно ваше решение» только при вопросе, gate, permission, лимите или unresolved unknown.
   Показывать причину, последнее автоматическое действие и конкретное доступное действие. Unknown нельзя скрывать.
5. Карточки агентов: роль, состояние, подтверждённая модель, полезный прогресс; терминал/параметры/output раскрываются.
   Очередь — читаемые строки со статусами. Технические ID доступны для копирования в деталях.
6. «Настройки»: шаблон, роли/резервы, профиль, политика запуска, создание/редактирование проекта и workspace.
   «Диагностика»: service lifecycle/порты, reconcile, операции, сравнение конфигов, попытки и журнал.
   При выключенном сервисе execute остаётся доступным через общий manager; кнопка service start не обязательна.
7. Визуально: явная иерархия заголовков, спокойная контрастная палитра, единая сетка отступов,
   статус текстом и цветом, ограниченная ширина длинных текстов, заметный focus, минимум одновременно видимых кнопок.

## Приёмка и проверки
- На desktop 1440×900 выбранная цель, прогресс и основное действие видны без прокрутки;
  нет таблицы ролей, портов или raw JSON в основном сценарии.
- На 390×844 страница не имеет горизонтального overflow; широкие таблицы прокручиваются внутри details.
- Свежий пользователь проходит подключение checkout и запуск fixture без технических промежуточных кнопок.
- Проверены empty catalog/no goals, idle, running, paused, recovering, needs_action, unknown, failed, completed,
  offline/unconfirmed и malformed response; сохранённое состояние не выдаётся за подтверждённое.
- Кликом/клавиатурой: execute→pause→resume→reply→completion, stop/retry, diagnostics;
  hidden actions действительно недоступны, backend проверяет их повторно.
- Двойной клик не создаёт второй request; pending отображается до результата; request_id сохраняется для reconciliation.
- Смена workspace и запоздалый ответ не обновляют чужой экран; черновик ответа/настроек и focus переживают polling.
- Доступны keyboard navigation, labels, focus-visible, aria-live только для значимых изменений;
  контраст обычного текста минимум 4.5:1. Не полагаться только на цвет.
- Browser fixture и screenshots desktop/mobile для idle/running/needs_action/offline; console без новых ошибок.
  Обновить runner_browser_check: реальные visible clicks вместо программного click скрытых элементов.
