# Самопроверка по классам дефектов

Используй проектный каталог дефектов из context.json, если он задан. Общий минимум:
- Авторизация: чтение, запись, ранние ошибки и replay.
- Конкурентность: порядок блокировок, повтор запросов, crash boundaries.
- Контракты: схема, API, UI, валидация и обратная совместимость.
- История и миграции: неизменяемые факты, upgrade и восстановление.
- Производительность: затронутые реальные команды на репрезентативных данных.
- Evidence: применимость класса, полный список затронутых мест, команда и результат проверки.

Не переносить доменные инварианты одного проекта в другой.
